## Next: the migration (Hossein, in his own environment — per his choice)

The design-time factory stays commented out; generate with the Api host as startup
(runtime config present in your environment):

```powershell
dotnet ef migrations add AddSpatialVersioning `
    --project src\IRI.App\Barg\Infrastructure\IRI.App.MakanNegarSaba.Ef `
    --startup-project src\IRI.App\Barg\Presentation\IRI.App.MakanNegarSaba.Api
```

Then **hand-add the spatial indexes** to the generated migration (EF cannot declare
them). In `Up()`:

```csharp
migrationBuilder.Sql(@"CREATE SPATIAL INDEX [SIX_Proposal_ProposedGeometry]
    ON [versioning].[Proposal] ([ProposedGeometry]);");

migrationBuilder.Sql(@"CREATE SPATIAL INDEX [SIX_FeatureHistory_Geometry]
    ON [versioning].[FeatureHistory] ([Geometry]);");
```

and in `Down()`:

```csharp
migrationBuilder.Sql("DROP INDEX [SIX_Proposal_ProposedGeometry] ON [versioning].[Proposal];");
migrationBuilder.Sql("DROP INDEX [SIX_FeatureHistory_Geometry] ON [versioning].[FeatureHistory];");
```

(Geography grid is the default for geography columns; no BOUNDING_BOX clause.)

Apply to the current working system (= staging, D44) with
`dotnet ef database update` (same `--project`/`--startup-project` pair) or by
`dotnet ef migrations script` + manual review, whichever you prefer.
